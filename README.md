# Telegram 다중 그룹 비상 관리자

그룹 소유자 계정에 문제가 생기더라도 **사전에 관리자 권한을 받은 봇**을 통해 그룹 운영을 이어갈 수 있도록 만든 한국어 관리 웹앱입니다.

## 구현 완료
- 여러 텔레그램 그룹 자동 등록 및 그룹별 실제 인원수·봇 권한 확인
- 회원 활동·입장·관리자 이벤트에서 이름, 사용자명, 숫자 ID 색인 저장
- 그룹별 회원 검색, 관리자 목록, 관리자 임명과 세부 권한 선택
- 그룹 이름·소개 수정, 회원 차단·해제
- 일반 회원 채팅 잠금/해제, 메시지 고정/삭제, 초대 링크 생성
- 그룹별 감사 로그
- 운영자 Telegram ID 허용목록 + 봇 개인 채팅 6자리 OTP + 2차 비밀번호
- Telegram 공식 웹훅 비밀 헤더 확인, 이벤트 중복 방지, PostgreSQL 저장
- 한국어 PC/모바일 웹 UI

## 필수 환경변수

| 이름 | 설명 |
| --- | --- |
| `BOT_TOKEN` | BotFather에서 발급한 봇 토큰 |
| `DATABASE_URL` | Neon PostgreSQL 연결 문자열 |
| `PUBLIC_URL` | Railway에 연결한 HTTPS 공개 URL (마지막 / 제외) |
| `WEBHOOK_SECRET` | 최소 16자, 영문 숫자 밑줄 하이픈으로 만든 웹훅 비밀 |
| `SESSION_SECRET` | 32자 이상의 랜덤 문자열 |
| `ADMIN_SECOND_PASSWORD` | 운영자 2차 비밀번호 |
| `OPERATOR_TELEGRAM_IDS` | 접근 가능한 운영자 Telegram 숫자 ID. 쉼표로 구분 |
| `PGSSL` | Neon에서는 기본 `true`, 필요 시 `false` |
| `PORT` | Railway가 자동 제공 |

실제 값은 **Railway 서비스 Variables**에만 저장합니다. GitHub에는 올리지 마세요.

## 배포 절차
1. Railway에서 새 프로젝트/서비스를 만들고 `BITMATE-del/bot_admin` 저장소의 `main` 브랜치를 연결합니다.
2. Neon에서 PostgreSQL DB를 생성하고 `DATABASE_URL`을 Railway Variables에 등록합니다.
3. 나머지 필수 환경변수 값을 설정합니다. Railway가 발급한 공개 도메인을 `PUBLIC_URL`로 사용합니다.
4. 배포가 성공하면 `https://도메인/health` 에 `{"status":"ok"}` 가 반환됩니다. 앱 시작 시 `setWebhook`이 자동 실행됩니다.
5. 허용된 운영자 Telegram 계정으로 봇에 직접 `/start`를 보냅니다.
6. 웹 관리자 페이지에서 본인의 숫자 Telegram ID를 입력해 인증번호를 요청합니다. 봇이 보낸 6자리 코드와 2차 비밀번호로 로그인합니다.
7. 봇을 운영할 각 그룹에 추가하고 **관리자 임명, 메시지 삭제, 회원 차단, 그룹 정보 변경, 초대 링크 관리, 고정** 등의 권한을 부여합니다.
8. 관리 페이지에서 연결된 그룹을 새로고침하고 권한 확인을 누릅니다.

### 필수 사전 준비
소유자가 정지된 이후에는 봇에 새로 권한을 부여할 수 없을 수 있으니 **정지 전에** 각 그룹에 관리자 권한을 부여하고, 다른 정상 운영자 계정도 OPERATOR_TELEGRAM_IDS에 등록하세요.

### 회원 검색 한계
Telegram 공식 Bot API는 전체 그룹 회원 목록을 일괄 조회하거나 이름으로 서버 검색하는 기능을 제공하지 않습니다. 봇이 가입 이후 확인한 메시지 작성자·신규 입장자·관리자 정보만 그룹별로 색인합니다. 기존 회원이 메시지를 쓰지 않는다면 검색에 나오지 않을 수 있습니다. 그룹의 개인 정보 보호 모드(Privacy Mode)가 켜져 있으면 봇이 수신할 수 있는 일반 메시지가 제한될 수 있습니다. 회원 검색을 위해 반드시 모든 메시지를 읽어야 하는 것은 아니지만, 그만큼 색인 범위가 제한됩니다.

### Telegram 관리자 권한의 한계
- 봇은 소유자 신분이 될 수 없고 소유권 이전이나 소유자 계정 복구가 불가능합니다.
- 봇이 다른 관리자를 임명하려면 미리 `can_promote_members` 권한을 받아야 합니다.
- 기존 관리자, 소유자에 대한 수정이나 제한은 Telegram이 허용하는 범위 내에서만 됩니다.
- 그룹의 실질적 권한이 확인되지 않은 작업은 Telegram API 오류가 웹 화면에 표시됩니다.

## 개발 실행
```bash
npm install
npm run check
npm start
```

Node.js 20 이상 사용. DB 테이블은 앱 시작 시 자동 생성됩니다. 실제 봇 토큰과 DB가 없으면 의도적으로 실행되지 않습니다.

## 운영 참고
- 사이트는 인증번호와 2차 비밀번호가 모두 필요하고, 브라우저 세션은 8시간입니다.
- 한 인스턴스 기준 OTP/세션을 메모리에 보관합니다. Railway 서비스를 한 대로 운영하세요. 확장 전에는 Redis 등 공유 세션 저장소가 필요합니다.
- 운영상 보안 로그는 DB에 저장하지만, 시스템 차원의 비밀번호 교체 및 사고 대응 절차는 따로 유지해야 합니다.
- 대규모 그룹에서는 Bot API 업데이트를 통해 파악한 회원만 저장되므로 검색 결과가 전체 그룹 구성원을 뜻하지 않습니다.

## @사용자명 검색 및 기존 회원 불러오기 (선택 기능)

기존 Bot API 관리 기능은 그대로 유지합니다. 더 넓은 검색을 사용하려면 [my.telegram.org/apps](https://my.telegram.org/apps)에서 **Telegram API ID/API hash**를 발급하고 Railway의 `bot_admin` 서비스 **Variables**에 다음 두 값을 등록하세요. 이것은 관리자 페이지 로그인 인증과는 별개의 *개발자 API 자격정보*이며, 개인 계정 로그인 코드를 봇에 제공할 필요는 없습니다.

- `TELEGRAM_API_ID` — Telegram 개발자 앱의 숫자 API ID
- `TELEGRAM_API_HASH` — 해당 앱의 API Hash (비밀값)

등록 후 자동 재배포가 완료되면 관리자 페이지에서 그룹을 선택하고 **Telegram @사용자명 직접 검색** 또는 **그룹 회원 불러오기(최대 500명)**를 사용합니다.

- @사용자명 조회: MTProto로 사용자 정보를 조회한 다음 Bot API로 **그룹 가입 여부를 재확인**하고, 그룹 가입자일 때만 관리자 후보로 표시합니다. 숫자 ID는 자동 확보합니다.
- 기존 회원 목록 동기화: MTProto `channels.getParticipants`로 조회 가능 범위만 최대 500명 저장하며, 비공개 그룹에 필요한 접근정보가 부족하거나 Telegram이 일부 명단을 제한하면 실패 또는 일부 결과만 반환할 수 있습니다. 5분당 최대 3회로 제한합니다.
- 저장된 회원 이름·닉네임·ID 검색: API ID/HASH 없이도 기존 기능 그대로 동작합니다.
- **전체 회원 100% 확보를 보장하지 않습니다.** 앱이 Telegram의 접근 제한을 우회하지 않습니다.
- 인증정보는 GitHub 또는 채팅에 올리지 말고 Railway 환경변수에 등록합니다.
